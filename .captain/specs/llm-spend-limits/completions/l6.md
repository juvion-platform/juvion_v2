### Permission contract

`('platform', 'update')` is wired via `authorize('platform', 'update')`. Per the RBAC defaults in `backend/src/shared/rbac/defaults.ts`, the three roles that have `platform:*` allow are super_admin, admin, and principal — the same trio the new `platformUpdateGate` allows. The role gate is the load-bearing check in tests (where `RBAC_ENFORCE=false`); `authorize()` is the documented contract that takes over in production.

## Spec-Gaps Discovered

1. **404 on a ghost college via `admin`/`principal` is unreachable.** The cross-college gate requires `req.collegeId === :id` for non-super_admins; a ghost college can never satisfy that, so a non-super_admin will always see 403 first, never 404. The test was adjusted to use super_admin (the only role that can produce a true 404 from this endpoint). Documented inline in the test. This isn't a bug — it's the security model expressing itself — but worth noting in the API docs (L8).
2. **404 audit cleanliness.** When `updateSpendLimits` throws 404, the College isn't loaded so no AuditLog row is emitted — correct behavior (we don't audit failed writes), but worth calling out in L8 docs if SREs ask "did the write happen?".
3. **No PATCH on the shared TestApi helper.** `backend/src/__e2e__/helpers/request.ts` only wraps `get/post/put/delete`. I inlined PATCH support inside the test rather than touching the shared helper for one-off use; if PATCH endpoints become common, the shared helper should grow a `.patch` method. Not a blocker.

## Notes / Design Decisions

- **Route mount order**: the new PATCH route is registered BEFORE `router.use(superAdminOnly)` so admins can hit it. The rest of `/api/colleges/*` remains super_admin-only as before — zero regression on existing endpoints.
- **`platformUpdateGate` over `authorize` for the load-bearing check**: e2e tests run with `RBAC_ENFORCE=false`, so `authorize()` becomes a pass-through. The simple role+cross-college gate is what actually enforces 403 in tests. `authorize()` stays in the chain to document the production contract.
- **Empty-body rejection** (`.refine()`): plan §1.5 doesn't explicitly require this, but the L3 service emits an AuditLog row on every call to `updateSpendLimits` even when `changes: []`. Rejecting `{}` at the validator keeps audit cleaner and matches the principle of least surprise.
- **No PATCH wrapper on TestApi**: deliberately kept this self-contained — touching the shared helper for one route would mean updating untouched test files; the inline supertest call is two lines and limited to this file.
- **Cross-college 403 vs 404 for `admin` on a ghost ID**: I picked 403 (gate fires first) over 404 because the gate runs before the service. This matches the RBAC mental model — "you can't write that resource at all" is a stronger statement than "that resource doesn't exist".
- **`authorize('platform', 'update')`** chosen over a more specific scope (e.g. `subDomain: 'spend-limits'`): no existing scope matches, and the overall contract `platform:update` already aligns with the RBAC defaults that pin this to admin/principal/super_admin. No new policy rows needed; existing defaults cover the new endpoint.
