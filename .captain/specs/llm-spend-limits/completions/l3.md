## Spec Gaps Discovered

1. **AppError doesn't carry structured detail.** Plan §1.5 says the 429 should carry `{ spent, limit, resetsAt }` in the body. Today's `AppError` is a plain `Error` subclass with `(statusCode, message)` — no detail field. The 429 currently surfaces with just the message string. **Recommendation:** L4 (the integration task) is the right place to either (a) extend `AppError` to carry a `detail` payload, or (b) format the 429 response body inline in the controller. I'd lean toward (a) for reuse. Either way, NOT a blocker for L3.
2. **Plan §1.5 declares `blocked: true` could be returned in the result object.** The actual contract is "throw on 100%, never return blocked: true to caller" — the `blocked` flag only exists on the result type for symmetry with a hypothetical non-throwing variant. Type contract preserved; no caller will ever see `blocked: true` in the current implementation. Documented inline at the type definition.

## Notes / Design Decisions

- **Lazy TTL read**: `cache.ts` reads `process.env.LLM_BUDGET_CACHE_TTL_SECONDS` on every `set` rather than at module load. Cleaner test ergonomics and matches the existing `AGENT_CACHE_TTL_HOURS` pattern in the cache spec.
- **`resetsAt` semantics**: Implemented as `now + 7d` — the moment when the OLDEST cost in the window will roll out. Approximate (the window slides continuously) but useful for the banner UX. Plan §1.6 calls this out.
- **No automatic spend invalidation on each LLM call** — kept as plan §1.6 specifies. Up to 60s of stale spend is acceptable; the alternative (invalidate-on-write) would defeat the cache.
- **`AgentAction.aggregate` $match casts collegeId via `new Types.ObjectId(collegeId)`** — required because the schema uses `Schema.Types.ObjectId` for `collegeId` and string equality won't match. Mirrors the pattern in the existing finance-agent worker.
- **Defensive validation in `updateSpendLimits`** — duplicates the Mongoose schema constraints (negative weeklyInr, threshold out of [1,100]) so we get a clean `AppError(400)` before the round-trip. Also catches the case where the schema validation message is opaque.
- **Field-level `changes[]`** only includes fields that were actually IN the request AND actually changed. `{}` body produces an audit with `changes: []` — caller sees this and can decide whether to no-op or still record (current code records).
