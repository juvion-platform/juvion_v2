## Spec-Gaps Discovered

1. **Array agent endpoints lack `budgetWarning` (deferred — L4 spec gap).** As called out in the task brief, `RiskScoreResult[]`, `Situation[]`, and `ReminderDraft[]` don't carry `budgetWarning` in the body today. Since the dashboard's `forecast-narrative` query fires on every dashboard mount and the budget can only grow within a window, hydrating the banner from the forecast response is sufficient for v1 — the array endpoints inheriting the same warning is purely additive future work. No frontend change required when those backends grow `budgetWarning`; the dashboard will keep reading from the forecast and the array consumers can opt in independently.

2. **429 detection is forecast-scoped.** The dashboard flips `budgetExceeded` only when the forecast call returns 429. A 429 from a chat stream or a risk-scores fetch wouldn't flip the dashboard into degraded mode today. This is acceptable for v1 because (a) the forecast is the most-frequently called LLM endpoint on this page and (b) the gate is a per-college rolling window — once the forecast returns 429, every subsequent call from this dashboard would too. If a future surface (e.g. an isolated chat session opened mid-page) needs to pre-empt this, a small upgrade is to expose `budgetWarning` on the chat `error` event and lift it the same way.

3. **`<AICommandBar />` chat-stream 429 not yet flipped.** The chat SSE error event has `status: number | undefined` but doesn't carry `budgetWarning` in the *error path* (only the *done* path does, per the task brief). Today, a 429 on chat would surface as a generic "Slow down — try again in a minute." bubble (existing copy from `errorMessageForStatus(429)`). Wiring chat 429 → `setBudgetExceeded` would require a callback prop on `<AICommandBar />`; deferred as out-of-scope v1 polish since the forecast's own check covers it on every page load.

4. **Section is edit-only.** New colleges (create flow) don't see the AI Spend Limits section because they have no `_id` to PATCH against. The original spec sketch implies the section appears on the College config form generally — the simplest path was to gate on `editing != null`. If we want to set limits at create time, the create flow would need to persist the new College first, then the section would re-mount on the next edit. Acceptable for v1 (defaults are applied at read time anyway).

## Notes / Design Decisions

- **No new toast lib.** Reused the inline-toast pattern from `PersonPhotoBlock` / `FinancialHoldsPage` (a small `useState<{kind, message}>` + `setTimeout`). Keeps the dep tree clean.
- **No `inp` / `lbl` constants.** `CollegeManagement.tsx` uses Tailwind classes directly inline (older convention from when this file was first written) — to stay consistent with the surrounding form, the new section follows the same inline-class pattern. The newer `inp`/`lbl` shorthand is used in the academics pages but switching `CollegeManagement` to it would be unrelated churn.
- **Pure helper exported for testing.** `formatRelativeFuture(iso, now)` accepts an optional `now` param so the test suite can assert deterministic strings without mocking `Date`. The component uses the default (real `Date`) at runtime.
- **`SituationCards` query gated with `enabled: !degraded`.** Originally I planned a `return null` only, but the React Query would still fire on mount before the guard ran. `enabled: !degraded` saves the round-trip — important when the entire reason we're degraded is that LLM calls cost money.
- **Save button disabled when not dirty.** Backend rejects empty bodies with a 400 (per L6 `.refine()`). Disabling the save button until the form is dirty avoids surfacing that 400 to the user as an error toast — UX matches the principle of least surprise.
- **`pct` clamped only at the bar render layer.** The banner copy uses `Math.round(w.pct)` straight from the payload (could be 100.5 if backend reports an in-flight overage). The bar's width is clamped to `[0, 100]` so a 110% pct doesn't overflow the rounded container — but the *copy* still says "110%" (truthful). When `exceeded`, copy switches to the "exceeded" string regardless.
