## Spec Gaps Surfaced

1. **Warning surface for array endpoints (risk-scores, situations, reminder-drafts).** Plan §1.8 wants `budgetWarning?` as a body field on these too, but their current return types are bare arrays. Wrapping them in `{ items, budgetWarning }` would break the frontend `RiskScoreResult[]` and `Situation[]` typings in `admin-portal/src/services/finance-agent.ts` and `admin-portal/src/pages/finance/FeeDashboardPage.tsx`. **Recommendation:** L7 surfaces the warning via an HTTP response header (`X-Budget-Warning`) set by a small middleware that reads the spend-check result from request-scoped storage. The header pattern is uniform across all 7 endpoints (including chat) and avoids body-shape breaks. Documented as TODO inline in `service.ts`.

2. **Chat 429 lands as an SSE error event, not a 429 status code.** Because SSE headers are flushed BEFORE the generator body runs, a service-side throw can't produce a clean 429 status. Today the generator yields `{ type: 'error', error: 'Weekly LLM budget exceeded' }` and ends the stream. The frontend's EventSource listener can pattern-match `error.event` to hydrate the banner. If a clean 429 status is required, the gate must move into the controller (`chatHandler`) BEFORE `res.flushHeaders()`. Current implementation matches the test's expectation; the design choice is documented in `service.ts`.

## Notes / Design Decisions

- **Gate placement strategy**: Each `handle*` function calls `assertWithinSpendLimit` once, near the top, AFTER `ensureCollegeId` validation. This is the simplest, most predictable pattern — and the 60s cache means the gate is effectively free on subsequent calls within that window. For `handleRiskScores`, the gate is conditional on `includeNarrative=true` (no LLM = no gate).
- **Atomic batch semantics**: For batch endpoints (`handleRiskScores`, `handleReminderDrafts`), the gate fires ONCE before the bounded-concurrency LLM calls. Either the entire batch goes through or the entire batch is blocked. No half-completed batches.
- **Existing service.test.ts not touched**: The pre-existing tests use random ObjectIds with no College document. With the gate now firing, they hit `loadLimits` → finds no college → returns defaults `(weeklyInr=0, alertThresholdPct=80)` → `weeklyInr=0` triggers immediate bypass. So all 6 pre-existing finance-agent suites stay green.
- **`AppError` extension is back-compat**: All existing throw sites pass only `(statusCode, message)` and surface as before. Only L3's 429 throw passes a `detail` payload, and the `errorHandler` includes it conditionally.
