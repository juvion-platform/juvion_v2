**Constants (1)**
- Exposes the expected MIME allowlist + caps (`ALLOWED_IMAGE_MIMES`, `PHOTO_MAX_BYTES`, `PHOTO_MAX_DIMENSION`, `THUMBNAIL_SIZE`, `PRESIGN_EXPIRY_SECONDS`).

**uploadStudentPhoto — happy paths (3)**
- JPEG → `original.jpg` + `thumb.jpg`; verifies put-call ordering, key shape, contentType, metadata = `{collegeId, studentId}`, persisted Person.photo, and that the thumb buffer the mock received decodes to a real 200×200 JPEG.
- PNG → `original.png` + `thumb.jpg` (thumb is always JPEG).
- WebP → `original.webp` + `thumb.jpg`.

**uploadStudentPhoto — validation (5)**
- GIF buffer → `AppError(400, /Unsupported image format/)`. No S3 puts.
- 8001×8001 → `AppError(400, /Image too large/)`. No S3 puts.
- `> PHOTO_MAX_BYTES` buffer (built by padding a real JPEG so the format detection still succeeds) → `AppError(400, /File too large/)`. No S3 puts.
- Random non-image bytes → `AppError(400)`. No S3 puts.
- Cross-college: studentId from college B with collegeId of college A → `AppError(404, /Student not found/)`. Person.photo on the cross-college student stays untouched. No S3 puts.

**uploadStudentPhoto — resilience (3)**
- Original put succeeds, thumb put rejects → original best-effort `deleteObject`'d once; error propagates; Person.photo never persisted.
- Person.findOneAndUpdate throws → both S3 keys are best-effort `deleteObject`'d (verified via `expect.arrayContaining`); thrown as `AppError(500, /Failed to persist photo metadata/)`.
- Replace flow: pre-existing photo had `.png` original + `.jpg` thumb. New JPEG upload lands `.jpg` original — old `.png` original is cleaned up; old `.jpg` thumb is **not** deleted (key is identical to new). Person.photo reflects the new state.

**deleteStudentPhoto (3)**
- Happy path → both S3 keys deleted, Person.photo set to null.
- Idempotent: photo already absent → no S3 calls, no error.
- Cross-college: wrong collegeId → `AppError(404)`, no S3 calls.

**getStudentPhotoUrls (5)**
- `variant='thumb'` → only `{thumb}`; `getPresignedUrl` called once with the thumb key + `{ expiresIn: PRESIGN_EXPIRY_SECONDS }`.
- `variant='original'` → only `{original}`.
- `variant='both'` (default) → both URLs; presigner called twice.
- No photo → returns `{}`, NOT 404.
- Cross-college → `AppError(404)`, presigner not called.

**EXIF handling (1)**
- Source: 100×100 JPEG carrying `orientation: 6`. Verifies the thumb buffer the mock receives, when re-decoded by sharp, has orientation undefined or `1` (i.e. `withMetadata({ exif: {} })` plus `.rotate()` baked the rotation into pixels and stripped the tag).

## Spec gaps / notes for downstream tasks

- **Sharp `withMetadata({ exif: {} })` is deprecated** in `sharp@0.33.5`'s type definitions in favor of `withExif()` / `withExifMerge()`. The deprecated form still works at runtime and the spec called for it explicitly, so we used it. If we ever upgrade sharp to a version that drops it entirely, the helpers `generateThumbnail` and `stripExifKeepFormat` are the only callsites — single-place fix.
- **Decompression-bomb safety.** The 8000×8000 dimension cap from `metadata()` is checked **before** the thumbnail/original re-encode pipelines run, so a malicious 50000×50000 PNG never gets decoded into pixels. `metadata()` is a header-only read; safe.
- **`buffer.length` cap is checked before `sharp.metadata()`.** This means a 6 MiB random-bytes payload fails-fast on the size check, not the format check. Tests cover both orderings (the "non-image" test uses a 43-byte buffer, and the "oversize buffer" test uses a real-JPEG-prefix + zero-padded buffer that's still well-formed for `metadata()`).
- **Cross-college isolation is double-bound.** `loadStudentScoped` filters Student by `{ _id, collegeId }` AND then re-filters Person by `{ _id: student.personId, collegeId }`. Either query missing yields a 404 with the same message ("Student not found"), so callers can't distinguish "student belongs to a different college" from "personId orphan" — by design.
- **Replace-flow caveat.** The cleanup deletes "old keys not in the new set" — i.e. it correctly handles the format-flip case (`.png` → `.jpg` original) and the same-format case (no orphan). It does **not** orphan-sweep the prefix; if a previous run left stray objects under `colleges/<cid>/students/<sid>/photo/` for any reason (pre-P4 dev seeds, manual S3 console writes), those are not cleaned by replace. P4 does NOT use `deleteObjectsByPrefix`; that's reserved for a future "purge all uploads for student" flow.
- **Person update failure semantics.** When `findOneAndUpdate` throws, we wrap into `AppError(500, 'Failed to persist photo metadata')` after best-effort S3 cleanup. The original error is intentionally not chained — surfacing internal Mongo errors over HTTP would leak schema details. If diagnostics are needed later, add a server-side `console.error` before the throw (matches the codebase's existing `[fee-pin]` warn pattern).
- **`declaredMime` is intentionally ignored.** Tests pass it on the JPEG happy path to lock the shape down, but the orchestrator never reads it — the actual MIME is whatever `sharp.metadata().format` decodes. This prevents "I said image/jpeg, but it's actually a TIFF" bypasses.
- **No app-startup wiring.** Per P1's contract, the S3 client builds lazily, so this module also never touches the network at import time. Tests don't need to set AWS env vars; production startup is unaffected.
- **Migration safety for legacy `Person.photo: String`.** P2 already established the field was unused in production, so the structured-shape switch is a no-op for real data. Mongoose drops legacy string values silently when the schema can't cast them. P4 does not add a migration — none is needed. (Documented inline at the top of `photo-service.ts` for future maintainers.)
- **Sharp version.** Confirmed `sharp@^0.33.5` works as expected: `metadata()` returns `format` ∈ `'jpeg' | 'png' | 'webp' | …`, `rotate()` autorotates, `resize(200, 200, { fit: 'cover', position: 'center' })` produces an exact 200×200, `withMetadata({ exif: {} })` strips orientation. No version pinning concerns.

## Public API summary (locked in)

```ts
// constants
export const ALLOWED_IMAGE_MIMES = ['image/jpeg', 'image/png', 'image/webp'] as const;
export const PHOTO_MAX_BYTES = 5 * 1024 * 1024;
export const PHOTO_MAX_DIMENSION = 8000;
export const THUMBNAIL_SIZE = 200;
export const PRESIGN_EXPIRY_SECONDS = 3600;

// types
export type AllowedImageMime = (typeof ALLOWED_IMAGE_MIMES)[number];
export type PhotoUrlVariant = 'thumb' | 'original' | 'both';
export interface UploadStudentPhotoOpts { collegeId; studentId; buffer; declaredMime?; }
export interface UploadStudentPhotoResult { original; thumb; contentType; sizeBytes; uploadedAt; }
export interface PresignedUrl { url; expiresAt; }
export interface PhotoUrls { original; thumb; }

// API
uploadStudentPhoto(opts): Promise<UploadStudentPhotoResult>
deleteStudentPhoto(collegeId, studentId): Promise<void>
getStudentPhotoUrls(collegeId, studentId, variant?): Promise<Partial<PhotoUrls>>
```
