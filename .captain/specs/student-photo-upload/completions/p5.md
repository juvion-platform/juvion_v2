## Test coverage map (14 tests / 3 describe blocks)

**Upload — POST /api/people/students/:id/photo (6)**
1. 200 happy: valid 50×50 JPEG → returns `{ original: '…/original.jpg', thumb: '…/thumb.jpg', contentType: 'image/jpeg', sizeBytes, uploadedAt }`; verifies two `putObject` calls were made.
2. 200 PNG: small 50×50 PNG → returns `{ original: '…/original.png', thumb: '…/thumb.jpg' }` (thumb is always JPEG).
3. 400 oversize file: 6 MiB buffer → multer's `LIMIT_FILE_SIZE` becomes `AppError(400, /File too large/)`; no S3 puts.
4. 400 unsupported MIME: `text/plain` via supertest's explicit `contentType` → fileFilter rejects with `AppError(400, /Unsupported image format/)`; no S3 puts.
5. 401 no auth → `authenticate` returns 401 before reaching the route.
6. 403 wrong role: `RBAC_ENFORCE='true'` for the duration of this single test; a `student`-role token is denied because the seeded RBAC defaults don't grant that role `people:update`.

**Delete — DELETE /api/people/students/:id/photo (3)**
7. 200 happy: pre-existing photo → both S3 keys deleted; `Person.photo` cleared on disk.
8. 200 idempotent: no photo present → returns `{ deleted: true }` with zero `deleteObject` calls (photo-service short-circuits).
9. 404 cross-college: caller's `collegeId` differs from the student's → `Student not found` propagates as 404; no S3 calls.

**Get URL — GET /api/people/students/:id/photo-url (5)**
10. 200 `variant=thumb` → only `thumb` key in response; `getPresignedUrl` called once with the thumb key.
11. 200 `variant=original` → only `original` key; `getPresignedUrl` called once with the original key.
12. 200 default (no variant) → both keys present; `getPresignedUrl` called twice.
13. 200 student has no photo → returns empty object `{}` (NOT 404), per photo-service contract.
14. 400 invalid variant (`?variant=garbage`) → `AppError(400, /variant/)`; presigner never called.

## Spec gaps / notes for downstream tasks

- **Test-file location vs. e2e config.** The brief specifies the file path `backend/src/modules/people/__tests__/photo-routes.e2e.test.ts`. Because `vitest.config.ts` matches `src/**/__tests__/**/*.test.ts` and `vitest.e2e.config.ts` matches only `src/__e2e__/**/*.test.ts`, this file runs in the **unit** suite, not the e2e suite. Practically that's fine — the unit runner sets up Mongo via `mongoMemory.ts` and we boot the full Express app via `import app from '../../../app'`. The "e2e" in the filename is descriptive of what the test does (full HTTP roundtrips against the actual app), not where it lives. If we ever want it to run under `vitest.e2e.config.ts` too, we'd need to move it to `backend/src/__e2e__/modules/people-photo-http.e2e.test.ts` (or expand the e2e include glob). Calling this out so the next reader doesn't grep the e2e suite for the file and conclude it's missing.
- **Cold-path test timeout.** The first multipart POST in the first describe block consistently takes ~3.2 s on first run (sharp warmup + S3 SDK lazy import + multer first parse + morgan first log line). Vitest's default `testTimeout: 5000` was tight enough that a slow client-side socket close after the response landed would push the test over the line. Solution applied: a `{ timeout: 30_000 }` override on that single test (mirrors the value used in `vitest.e2e.config.ts`). All subsequent upload tests run in ~50–120 ms since the modules are already loaded.
- **`req.params.id` cast.** Express 5 typings widen `req.params.id` to `string | string[]` under `noUncheckedIndexedAccess`. The existing `controller.ts` uses `as string` everywhere; we use `as string | undefined` followed by an explicit `if (!id)` guard, which is one notch safer (catches the `undefined` case explicitly) and produces the same downstream behavior. If we ever want a single house style, a tiny `requireParam(req, 'id')` helper in `controller.ts` would let every handler drop the cast — consider for a future refactor sweep.
- **`fileFilter` rejection signal is a plain `Error`.** Multer's `FileFilterCallback` accepts `cb(error: Error)` to reject. Throwing an `AppError(400, …)` directly from the fileFilter would bypass the `multerErrorHandler`'s remap step (Express invokes the next error middleware regardless of error type, but our remapper checks `err.message === UNSUPPORTED_FORMAT_MESSAGE`). We chose a plain `Error` with a sentinel message to keep the remap location single-sourced. Trade-off: the sentinel string is a string-equality check that would silently drift if the message ever changed without updating both spots. They live in the same file (constant `UNSUPPORTED_FORMAT_MESSAGE`), so the risk is low.
- **No app-startup wiring needed.** The S3 SDK is lazy (P1) and photo-service is import-clean (P4). Routes wire up only at first import of `routes.ts`, which already happened as part of `apiRouter` mounting. No env var check is required at boot — misconfigured `AWS_S3_BUCKET` will surface as `AppError(503)` from the first request that touches S3.
- **Multer 1.x vs. types 2.x.** The package uses `multer@^1.4.4` (the 1.x line) but `@types/multer@^2.1.0`. The two are intentionally compatible at the API surface used here (`multer.memoryStorage()`, `multer.MulterError`, `Options.limits.fileSize`, `Options.fileFilter`). If multer bumps to 2.x runtime, the only file to revisit is `photo-controller.ts` — `MulterError.code` is the only field referenced.
- **No multipart body-size guard above multer.** `app.ts` has `express.json({ limit: '10mb' })` for JSON bodies, which multipart bypasses. The 5 MB cap is enforced by multer alone via `limits.fileSize`. That's the contract the brief specified; flagging in case a future reviewer expects an upstream `express.urlencoded` limit too.

## Public route surface (locked in)

```
POST   /api/people/students/:id/photo       authorize('people','update')
                                             multipart/form-data, field=file
                                             → { original, thumb, contentType, sizeBytes, uploadedAt }

DELETE /api/people/students/:id/photo       authorize('people','update')
                                             → { deleted: true }

GET    /api/people/students/:id/photo-url   authorize('people','read')
                                             ?variant=thumb|original|both (default both)
                                             → { thumb?: { url, expiresAt }, original?: { url, expiresAt } }
```
