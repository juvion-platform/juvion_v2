## Component shape

```tsx
interface Props {
  studentId: string;
  studentName?: string;
  size?: number;          // pixels, default 32
}
```

Three render branches:

1. `isLoading` → `<div className="rounded-full bg-slate-200 animate-pulse" />` sized to `size`. `aria-hidden`.
2. Success + `data?.thumb?.url` (and `<img>` not yet broken) → `<img src={url} loading="lazy" onError={() => setBroken(true)} className="rounded-full object-cover bg-slate-100" />` with descriptive `alt` (`{name} photo` or generic).
3. Error / no-photo (`data` is `{}`) / `<img>` failed to load → gradient initials avatar (`bg-gradient-to-br from-teal-400 to-blue-500 text-white font-semibold`), centered. Initials = first letter of first and last name parts (1–2 letters), `?` if no name.

Initials computation handles edge cases: empty/whitespace name → `?`, single name → first letter only, multi-word → first + last letter (so "Priya Ravi Kumar" → "PK", "Priya" → "P"). Font size scales with `size` (40% of size, min 10 px).

## Performance notes (for future v2)

This is the touchy part the brief flagged.

**v1 (now):**
- 50 rows per page → 50 simultaneous `GET /photo-url?variant=thumb` calls on mount. Each presigns one S3 URL backend-side and returns ~200 B. Cheap individually, chatty in aggregate.
- React Query auto-dedupes by key, so if a student appears twice in the list (shouldn't, but) only one request fires.
- `staleTime: 30 min` means moving between pages and back doesn't re-fetch.
- `retry: false` means a backend hiccup or 500 falls through to initials immediately — no retry storms.
- `<img loading="lazy">` defers the actual S3 GET (the bytes) until the row scrolls into view. Browsers honor this for `<img>` natively. So the chatty part is the 50 presign GETs, not the 50 image downloads.
- `onError` on the `<img>` catches expired/broken presigns and falls back to initials gracefully.

**v2 follow-up (don't build yet; flag if pagination perf is bad):**
- Backend batch endpoint: `POST /api/people/students/photo-urls` with `{ studentIds: string[], variant }` returning `Record<studentId, StudentPhotoUrlsResponse>`. One round-trip per page instead of 50.
- Or: backend embeds `photo: { thumbUrl, expiresAt }` directly into the `listStudents` response, eliminating the extra hop entirely. This is the cleanest UX-wise but couples list pagination to S3 presign latency.
- Decision: defer to v2. The 50-presign load is well within budget; do not optimize prematurely.

- **TypeScript strict mode + `noUncheckedIndexedAccess`** is enabled. The `name.trim().split(/\s+/).filter(Boolean)` chain produces `string[]`, but indexed access (`parts[0]`, `parts[parts.length - 1]`) returns `string | undefined` under that flag, so I used `?.[0] ?? ''` chaining + an explicit `parts.length === 0` guard. No `any` anywhere.
