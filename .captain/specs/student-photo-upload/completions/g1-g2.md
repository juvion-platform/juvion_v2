# G1 + G2 — Generalize S3 prefix helper + photo-service over PersonEntityType

**Status:** GREEN. Focused suites green; full backend suite green; typecheck clean.

## Goal

Lift the student-only S3 helper and photo-service onto a generic
`PersonEntityType = 'students' | 'faculty' | 'staff' | 'parents'`
discriminator so the same upload/delete/presign machinery serves every
person-linked entity. Person remains the canonical storage location for
the photo metadata; the entity row is just the lookup hop to find the
right Person via its `personId` ref.

Compat shims preserve the student-only API surface so existing call
sites (photo-controller.ts, frontend service, e2e tests) keep working
on this commit. G3 will switch the controller to the generic API.

## Spec gaps / decisions made

1. **Error message wording shifted from `Student not found` to `students not found`.** The brief specified per-entity-type errors (`${entityType} not found`), which yields the lowercase pluralized slug verbatim. Two existing test assertions on the student-only path (one in `photo-service.test.ts`, one in `photo-routes.e2e.test.ts`) had to be updated. Decision: keep the entity-type slug verbatim in the message — it's the simplest representation and matches the URL slug the user already sees. If we want pretty error messages ("Student not found" / "Faculty member not found"), we'd add a label table; deferring that to G3+ since it's purely cosmetic.

2. **S3 PutObject metadata shape changed.** Was `{ collegeId, studentId }`; now `{ collegeId, entityId, entityType }`. This is observable to anyone reading raw S3 metadata downstream — there's nothing in the repo that does today (verified via grep), but flagging it for the next reviewer in case external observers (e.g., a future S3 Lambda trigger) consume this metadata.

3. **`Model<unknown>` cast for the entity-type map.** The four models (Student, Faculty, Staff, Parent) all have different document interfaces, so a tighter generic would require a discriminated union over the doc types. Since the only field we read off the row is `personId` and we re-cast at runtime via `as { _id: unknown; personId?: unknown } | null`, the loose `Model<unknown>` cast is the cleanest way to keep the map heterogeneous without `any`. No `any` anywhere in the diff.

4. **`UploadStudentPhotoResult` reused for the generic return type.** Renaming would cascade through the test file and the controller (G3 territory). Kept the legacy name; it's accurate ("the result of uploading a person's photo, in the same shape we returned for students") and the structural shape is unchanged. We can rename in G3 alongside the controller refactor if it's worth the churn.

5. **`Parent` model has a `linkedStudents` array, but we ignore it for photo lookup.** Parent.personId points to a Person — that Person is where the photo lives. The `linkedStudents` array is unrelated to photo storage. Confirmed by reading the Parent schema.

6. **No hard tenant-cross check in the test for `loadEntityScoped`'s "Person belongs to a different college" branch.** The defense-in-depth re-confirm for Person is exercised indirectly through every cross-college test (the Person query is also scoped by `collegeId` so any cross-tenant traversal would 404 there too). A targeted unit test for that exact branch would require corrupting the DB (entity in college A, Person in college B) and is brittle vs. value. Skipped per Pareto.

## Compat shim removal plan

Three shims are kept for one release:

| Shim | Removal trigger |
|------|-----------------|
| `studentUploadPrefix(collegeId, studentId)` in `s3-client.ts` | After G3 lands and the controller migrates to `entityUploadPrefix`. No external callers in tree (verified). |
| `uploadStudentPhoto(opts)` in `photo-service.ts` | After G3 swaps the controller's `uploadStudentPhoto` call to `uploadEntityPhoto`. Frontend (G4/G5) does not call this directly — it goes through the HTTP route, so no frontend coupling. |
| `deleteStudentPhoto(collegeId, studentId)` and `getStudentPhotoUrls(collegeId, studentId, variant?)` | Same as above — removed alongside G3's controller switch. |

Recommended: delete all four shims in the same commit as G3's controller refactor, with one final grep to confirm no remaining call sites:

```
grep -rn 'studentUploadPrefix\|uploadStudentPhoto\|deleteStudentPhoto\|getStudentPhotoUrls' backend/src admin-portal/src
```

That grep should be empty after G3 + G4/G5 land. If anything remains, route it through the generic API before removing the shims.
