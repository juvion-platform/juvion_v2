## Behavior locked in

- Lazy singleton: `S3Client` is constructed on first use, not at
  module load. App boot survives missing AWS env (errors surface as
  503s when an upload is actually attempted).
- `AWS_S3_ENDPOINT` semantics: when set, `forcePathStyle: true` is
  applied. When unset, `endpoint` and `forcePathStyle` are both
  omitted so the SDK uses virtual-hosted addressing against AWS.
- `ServerSideEncryption: 'AES256'` is mandatory on every upload.
- Key shape: opaque strings, IDs not validated here — the calling
  service validates ObjectId shape and tenant scoping.
- `studentUploadPrefix(collegeId, studentId)` is the sole place
  that knows the layout `colleges/<cid>/students/<sid>`. P4
  (photo-service) and any future student-upload feature must go
  through it.

## Spec gaps / notes for downstream tasks

- **`AWS_S3_ENDPOINT` semantics**: When unset, the implementation
  passes neither `endpoint` nor `forcePathStyle` to the SDK so AWS
  defaults apply. The spec didn't pin the unset behavior, but this
  is the only safe default for production.
- **NoSuchKey detection** uses `err.name === 'NoSuchKey'`. AWS SDK
  v3 surfaces `NoSuchKey` consistently this way for delete calls;
  `404`-on-DeleteObject is not actually emitted by S3 in production
  (S3 always returns 204 even for missing keys), so this branch is
  defensive cover for SDK versions / path-style endpoints (LocalStack
  has been observed to return errors here). No-throw was the spec
  contract; we honor it for either shape.
- **DeleteObjects partial-failure handling**: We return the count of
  objects we *asked* to delete, not the count of `Deleted` entries
  in the response. AWS may return a non-empty `Errors` array on
  partial failure; this implementation does not surface that today.
  If the caller needs strict "deleted vs failed" accounting (e.g.
  for retry logic), P4 should layer it on top — out of scope for
  P1.
- **No app-startup registration**: per task rules, the client is
  not registered in `app.ts`, `server.ts`, or any startup hook. P4
  imports the helpers directly.
- **No new npm deps**: only `@aws-sdk/client-s3` and
  `@aws-sdk/s3-request-presigner` (already installed at
  `^3.1037.0`).
- **Strict TS / no `any`**: command inputs are typed via the SDK's
  command classes; private helpers use either `S3ClientConfig` or
  narrow inline shapes. The single `unknown` cast is in
  `isNoSuchKeyError`, where the SDK's error type isn't statically
  known (mirrors how mongoose / bullmq error narrowing is done
  elsewhere in this codebase).
